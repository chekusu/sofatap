# Sofatap iPhone controller

Native SwiftUI iPhone app, iOS 17+, no third-party libraries. Current source and TestFlight release: version **1.0, build 16**; `project.yml` is the source of truth for these numbers. The interface and permission descriptions support [12 languages](../docs/APP-LANGUAGES.md): English, Simplified Chinese, Japanese, Spanish, French, German, Brazilian Portuguese, Korean, Arabic, Hindi, Russian and Indonesian. English is the fallback; translation availability does not guarantee on-device speech recognition for every language/device combination.

Use [receiver 0.7.2 beta.1](https://github.com/chekusu/sofatap/releases/tag/v0.7.2-beta.1) for Windows, macOS or Linux and iPhone build 16 for the complete reconnect fix. Desktop QR platform/name metadata requires build 15 or newer; older receiver 0.7.0 codes remain supported. Supported Windows/Mac fields offer live editing; Linux and unsupported fields use review-and-send. Build 16 is available in public TestFlight and its installation on the dedicated iPhone is verified. See the [receiver release record](../docs/verification/receiver-0.7.2.md) and [TestFlight distribution record](../docs/verification/testflight-1.0-16.md) for actual input-test limits and the separate formal App Store review status.

Open `SofaTap.xcodeproj` in Xcode. Select your company's Apple development team and a connected iPhone to install. The repository contains no provisioning profiles or developer account identifiers. `project.yml` is the reproducible XcodeGen source; use `xcodegen generate --spec ios/project.yml` from the repository root after changing it.

The receiver's QR code or full `sofatap://pair?...` URI supplies the host, port, secret and leaf certificate fingerprint, plus optional platform/name labels. Labels identify a candidate; they never replace certificate pinning or credential authentication. Pairing credentials are stored in Keychain with `WhenUnlockedThisDeviceOnly`. Native WSS trusts only that exact host, port and certificate; redirects are rejected. Local-network ATS permission is scoped with `NSAllowsLocalNetworking`; there is no global ATS exemption.

Current development source restores the saved selection when reopened and retries temporary connection failures while the phone app is active, with delays capped at 30 seconds. It retries a temporarily occupied receiver slot but stops on authentication, certificate or protocol rejection. Manual disconnection, switching targets and backgrounding cancel pending retries. Reconnection establishes a fresh transport only; it never resends uncertain text or gestures. If Keychain is temporarily unreadable at launch, returning to the active app retries that read. See the [reconnection verification record](../docs/verification/reconnect-2026-10-15.md) for release and device-test limits.

The everyday interface is one large rounded touch surface. The top-left selector combines the logo, current device name/type and connection state; it opens **My Devices**. The top-right question mark opens a separate illustrated guide. The microphone and keyboard controls sit at the bottom of the pad, with animated toggle/press feedback and haptics. The edge-scroll strip is inside the pad's right edge. Connection and recording states have accessible labels.

The current development source also adds **Gesture Settings** beside the guide. Three presets and nine assignable gestures keep separate computer/TV preferences on the iPhone, with timing, natural scrolling, reset and an offline practice sheet. See [gesture settings](../docs/GESTURES.md). This development feature is not included in published build 17.

In **My Devices**, choose **Scan QR Code** under **Add Device**. The next sheet shows the camera above platform information, without a device-type selection. The code determines the connection route; after authentication, keep the suggested name or enter a nickname. Saved devices can be switched, renamed, disconnected or removed from their menu. Nicknames and removal apply only to this iPhone; removal does not revoke other phones. Android/Google TV and LG webOS adapters remain development previews with no qualified physical TV model; LG uses manual IP entry. The desktop 0.7.2 release does not distribute an Android TV receiver APK.

A slowly flowing dot matrix fills the entire pad, without a separate mouse arrow. Touch displaces and bends nearby dots, which settle back after release; single and double taps retain distinct ripples, and a hold strengthens the local deformation. Ambient animation pauses while inactive, detached or unable to control; Reduce Motion uses a static grid and simpler touch feedback. Effects do not mirror the desktop pointer or acknowledge desktop actions. Slide one finger to move and tap anywhere once for a left click. Double-tap within the invisible left half for two left clicks, or the right half for two right clicks. Only the guide illustrates these physical halves; the touchpad shows no dividing line or extra labels, including in RTL languages. Hold still for 300 ms then move to drag, and slide two fingers to drag content naturally. The right-edge strip follows scrollbar direction: down scrolls down. There is no mouse-mode selector or separate click/drag panel. A right-half double-tap must not send an accidental left click; lifting, cancelling or leaving the app releases a drag. Desktop touch movement is sent directly from UIKit callbacks, with up to twelve outstanding movement ACKs over LAN or eight over the peer route; returning ACKs immediately drain fresh coalesced movement. Supported iPhones request up to 120 Hz while touching the desktop pad; the actual rate is chosen by iOS. Fresh relative deltas accumulate while waiting; unsent batches expire after 120 ms, and a stalled ACK closes the send window. Desktop touch gain ranges from 1× for precise motion to 2.2× for fast strokes, with a 3-point start threshold; a hold still survives up to 7 points of early finger roll once the finger rests for 100 ms. TV pointer semantics remain separate. The receiver independently releases held buttons on disconnect or idle timeout. See the [interaction specification](../docs/INTERACTION.md).

Only when needed, text appears in an inline `UITextView` so iOS keyboards, system dictation and Typeless can compose normally. A supported current field opens in live mode by default: its complete existing text and native selection are imported, then confirmed keyboard edits, Backspace, Select All → Delete and selection changes synchronize without Send. Marked IME composition stays on the phone until committed. Windows currently supports native Edit/RichEdit controls; Mac requires writable AX selected-text and selection-range attributes. Unsupported fields, including many browser and custom controls, Linux and older receivers use a separate review-and-send draft. Sofatap does not append an extra Return after the text; line breaks included in a fallback draft are sent as Enter and may submit a form or message in the destination app.

In fallback draft mode, keyboard Backspace deletes local unsent text first. With an empty draft and no retained sent-text receipt, it sends Backspace to the computer. Clearing the local draft resets that receipt; it does not delete computer text. Focus a computer text field before using remote Backspace. The separate computer Backspace icon targets that input position without deleting the phone draft, including a nonempty fallback draft. Live editing keeps its existing deletion synchronization. Uncertain delivery must not be retried automatically. These gesture and Backspace changes are available in iPhone build 16; build 15 retains its earlier behavior.

The bottom microphone starts Sofatap's own on-device recognition after an explicit tap and microphone/Speech permission. In live mode, partial results and subsequent corrections replace the active dictated span and synchronize with the computer. Tap again to stop; stopping does not undo already synchronized text. In fallback mode, review the local draft and tap **Send**. Unsupported recognition devices/languages fall back to keyboard input rather than cloud recognition.

The editor preserves UIKit changes that have not yet reached its delegate when SwiftUI renders other state. Deliberate clears and speech replacements take precedence over earlier edit callbacks; replacements wait for an active marked composition to finish. Run `bash ios/scripts/test-draft-editor.sh` on macOS for offscreen UIKit regressions covering this ordering, Unicode, marked text, selection and external replacement. These checks create no window and send no computer input; real keyboard and microphone acceptance remains a separate device test.

Live field text is normally ephemeral: the imported value, selection and subsequent live edits stay in memory and do not overwrite the saved `localTextDraft` in UserDefaults. If the user explicitly confirms reusing retained text as a draft for another target, that draft is saved locally; switching devices alone does not send it. A live session uses an opaque session UUID, strictly increasing revisions and one acknowledged snapshot at a time. A native focus, selection or text conflict, disconnect or uncertain write pauses synchronization and never replays the edit automatically. Reopen the editor deliberately after inspecting the computer. A successful live ACK includes exact native text/selection readback; it does not mean the target app saved a document or submitted a form.

The separate fallback draft stays local until Send and persists in UserDefaults for recovery. Unsent and uncertain fallback drafts remain available. A successful fallback send means the receiver submitted input events to the system, not that a target field consumed or saved them. Pending/uncertain/success markers survive process termination; uncertain or unchanged accepted text requires review before a manual resend. Nothing is replayed on reconnect. Clear the fallback draft with the trash icon below the composer. The adjacent arrow toggles the keyboard; the circular Send button sits inside the text field with reserved text space. In live mode, deleting or clearing text edits the actual computer field.

A compatible receiver can automatically open the keyboard when a new supported native or web text field becomes editable and focused; an active drag finishes before it opens. This background probe reads accessibility metadata, never field contents. Once the editor opens, the separate live-session request reads and transfers the complete supported field text and selection. Detection and live editing have different compatibility scopes; a browser can summon the keyboard yet still use fallback sending. Protected, read-only or unknown targets do not trigger the keyboard. Protected targets also disable Sofatap's microphone; the manual keyboard remains available. Dismissing the keyboard keeps it dismissed for that target. Linux detection depends on an optional AT-SPI bridge and still uses fallback text input. See [focus detection and platform limits](../docs/TEXT-FOCUS.md).

In My Devices, the desktop Connection mode selector is shown only while a matching receiver advertisement is currently visible on an AWDL interface. Unknown, unavailable, disabled, and unsupported peer environments hide the selector and continue using LAN. Discovery continues while this settings screen is active even if Regular Wi-Fi is selected, so users can switch back; it stops when the screen closes or the app becomes inactive. The selector offers Auto (prefer direct) and Regular Wi-Fi. The choice persists across launches and applies to desktop connections. Changing it reconnects an active session, discards pending input, and invalidates previous discovery callbacks; a manually disconnected device stays disconnected. The main status shows the actual route, including regular Wi-Fi when Auto falls back.

Compatible Mac receivers advertise an optional Apple peer route. The phone automatically prefers a matching Bonjour service scoped to an AWDL interface; service discovery is only a routing hint, and the original certificate pin and pairing token still authenticate the connection. Unsupported receivers and unavailable peer discovery use the saved LAN endpoint. A retryable peer connection failure selects LAN for the next reconnect, including a failure after authentication; certificate and authorization failures remain terminal. A reconnect never replays unacknowledged input. The connected peer route uses the status string “已连接 · 设备直连”; ordinary LAN uses the normal connected label. Discovery is bounded to three seconds. The `SofatapPeerTransportEnabled=false` launch/defaults override disables peer selection for diagnostics; absence of that override enables automatic selection. AWDL availability and latency depend on the devices and radio environment; the route is not a guarantee of jitter-free input.

Launching with `--demo` never connects to a computer. The top-left selector explicitly labels the offline interface demo and uses an amber play badge; its accessibility value also identifies the preview. A receiver with `inputAvailable=false` disables controls. Current receivers distinguish dry-run, missing Mac Accessibility permission and an unavailable desktop; old receivers show a generic unavailable state. Heartbeats refresh this state. Backgrounding disconnects and stops capture; temporary inactivity for the app's own permission prompt pauses pointer input without cancelling the permission request.

## Privacy manifest

`SofaTap/PrivacyInfo.xcprivacy` declares `UserDefaults` (`CA92.1`) for this app's local draft and delivery markers, and system boot time (`35F9.1`) to discard motion samples older than 150 ms. The uptime value and motion timestamps are not transmitted. XcodeGen includes the manifest in the app's resources; verify it is present in the final `.app` before distribution. See Apple's [required-reason API guidance](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api).

This declaration covers required-reason APIs, not the separate App Store privacy answers or a privacy policy. The client sends control events and text directly to the paired computer and keeps credentials in Keychain. Opening a live editor transfers the focused supported field's complete text and selection to the phone over pinned TLS; it remains in app memory unless the user explicitly confirms retaining it as a draft for another target. The receiver retains bounded text-bearing ACKs in connection memory for duplicate suppression, until disconnect. It does not log field text. The separate review-and-send draft is stored locally for recovery. See the [Privacy Policy](../PRIVACY.md).

After an explicit microphone tap and permission, supported speech recognition runs on the iPhone. Audio is not uploaded, sent to the paired computer or silently routed to cloud recognition. Partial recognized text and revisions are transmitted during live editing; fallback text requires Send. Leaving the app or interrupting capture stops the microphone. System dictation and third-party keyboards have their own data handling. Review the final app, companion receiver and future SDKs against Apple's [data collection definition](https://developer.apple.com/app-store/app-privacy-details/#data-collection) before completing distribution metadata.

## Build fallback for mismatched Xcode SDK/runtime installations

Normal Xcode project builds are preferred. If `xcodebuild` cannot select a destination because the installed SDK is newer than available simulator runtimes, the following compiles and links the exact same native source directly against the selected SDK without installing anything or altering Xcode:

```sh
./ios/scripts/build-manual.sh simulator
./ios/scripts/build-manual.sh device
```

The first prints an adhoc signed simulator `.app` path in a temporary staging directory; install it with `xcrun simctl install <simulator-id> <app-path>`, then use `xcrun simctl launch <simulator-id> com.chekusu.sofatap --demo`. Its synthetic `SIMULATOR0` app identity in `Simulator.entitlements` enables the native simulator Keychain through Xcode-style simulated Mach-O entitlement sections; the macOS host code signature has no restricted iOS entitlements. This identity is not an Apple development team and is never used for physical signing. The second prints an unprovisioned ARM64 device `.app`, which proves device compilation/linking and requires normal Xcode development signing for installation. Both modes derive version/build from `project.yml` and copy the localized interface and permission resources, with English as the fallback language. Staging outside Documents avoids FileProvider metadata interfering with codesigning. This fallback is not an App Store archive/export pipeline; use a normal Release archive and distribution export for TestFlight.

Historical UI artifacts: [offline layout](../docs/images/sofatap-single-screen.png) and [dot-matrix preview](../docs/images/sofatap-touch-effects.mp4). These predate the build 15 device selector and guide layout; they are not current release screenshots. To reproduce the visual replay in the simulator, launch with `--demo --preview-effects`: the renderer plays three 8-second interaction cycles, then returns to the slow ambient field after 24 seconds. This simulator-only replay generates no synthetic touch events, controller actions or network events.

Offline simulator screenshots and recordings demonstrate local UI and effects, not physical-device frame rate, touch latency or desktop input. The [0.7.1 receiver record](../docs/verification/receiver-0.7.1.md) confirms build 15 installation and a physical camera scan, Linux identification, naming, rename and persistent reconnect against an isolated Linux ARM64 receiver. Mac/Windows optical pairing and naming remain pending in that record; this run sent no real desktop input. The [0.7.0 physical Windows record](../docs/verification/realtime-input-0.7.0.md) separately confirms existing RichEdit text import, multilingual/emoji/newline append, real keyboard deletion, Select All and deletion to empty. Live speech and additional cases remain pending. The [0.6.0 record](../docs/verification/2026-10-13-iphone-input.md) covers gestures, microphone recognition and explicit sending. These scoped records do not establish Mac live editing, Typeless, physical Wayland input or application-wide compatibility. Shared-Mac receiver tests must follow [AGENTS.md](../AGENTS.md) and keep Yomado display/input isolation.


## Historical Windows Hello PIN direction (0.6.0 / build 9; still disabled)

The account-password unlock experiment has been retired. Sofatap no longer offers account-password enrollment, replacement or Face ID submission. The ordinary receiver's legacy `unlock` advertisement is ignored, cached password capabilities are not activated, and the retained experimental controller has a fixed disabled gate on enrollment, authentication and network requests. Its protocol/binding source remains for review; it must not be relabeled as a Windows Hello PIN implementation.

If an earlier experimental build saved a credential, **My Devices** exposes only **删除旧版解锁记录** to delete that iPhone's legacy Keychain record and service authorization. This cleanup reads only binding metadata and deletes the items; it does not read the protected password, request Face ID or contact Windows. The Face ID purpose string is removed because the current UI cannot request biometric authentication.

The intended product direction is saved Windows Hello PIN use after explicit Face ID, with a manual phone pointer/PIN fallback while Windows is locked. Neither path is enabled in this build. Both depend on a separately verified Windows secure-desktop component and protocol. Ordinary desktop controls remain unchanged and do not gain lock-screen access. PIN input must not reuse the ordinary text composer: fallback drafts persist in UserDefaults and both modes support dictation. A future manual PIN path needs its own native input surface, no clipboard/dictation or stored PIN, no secret echo, and no automatic resend after an uncertain result.

Legacy protocol/binding checks (synthetic fixtures, no real password, biometric prompt or desktop input):

```sh
xcrun swiftc -swift-version 5 ios/SofaTap/Core/SavedDevice.swift ios/SofaTap/Core/Pairing.swift \

  ios/tests/UnlockProtocolTests.swift -o /tmp/sofatap-unlock-protocol-tests
/tmp/sofatap-unlock-protocol-tests
```
