# Android phone controller beta — October 21, 2026

## Scope

`android/controller`, version `0.1.0-beta.1` (code 2), is the native Android phone/tablet **remote controller**. Public APKs use `com.chekusu.sofatap`; debug QA uses `com.chekusu.sofatap.dev` so it can coexist without replacing user data. `android/receiver` remains the separate Android/Google TV receiver. No iPhone or production receiver input implementation changes are required by this beta.

The free client includes QR/paste pairing, certificate-bound saved devices and rename, foreground reconnect, mouse/TV gestures, native gesture settings and local practice, keyboard input and provider-dependent foreground dictation. Supported computer fields use the existing `textBegin/textSync/textEnd` protocol for text, UTF-16 selection and deletion; fields without live support and TV editors retain explicit Send. Speech partial hypotheses replace the original selection rather than duplicating earlier hypotheses. Recognition quality and availability depend on the installed Android provider, which may process audio online.

Computer and TV-pointer profiles are stored independently. Nine configurable gestures, three presets, hold/double-tap timing and natural scrolling match the iOS model. TV directional mode remains fixed directional navigation; unavailable actions are disabled without discarding saved mappings. Keyboard and microphone positions remain consistent between modes, with TV controls at the lower right. English, Simplified Chinese and Japanese are included.

## Completed software checks

- JDK 17 / Android SDK 36: debug/release APK and instrumentation compilation, 114 ordinary JVM tests and Android lint passed (0 errors, 29 warnings). The optional production compatibility test is skipped by an ordinary run and was executed separately with a fresh owned recording harness.
- The opt-in production integration passed against the actual receiver TLS/auth/protocol server with a recording input sink. It covers Unicode ordinary input, saved identity reconnect, click/drag/scroll, live text begin/sync/end, UTF-16 selections, full deletion, duplicate IDs, stale revisions and reread/restore. The new `--live-text` harness edits synthetic in-memory text only; its 20 self-checks passed. No desktop input was injected. The listener was stopped after testing and its private pairing file removed.
- Twelve native instrumentation tests passed on a Pixel 6 / Android 15 API 35 ARM64 emulator, together in the final combined run: eight controller tests, two gesture settings/practice tests and two TLS/native JSON tests. They cover the actual Android Activity, native IME composition/commit, selection-only updates, full-field deletion, exact-once empty Backspace, synthetic speech corrections, touch dispatch, TV OK/navigation/text epochs, encrypted saved credentials, persistence, portrait/landscape with keyboard and retained selection, settings changes/presets/practice, and malformed native JSON rejection.
- Ten packaging validation tests passed (including password-source and non-interactive signing safeguards). The release script requires a clean exact Git SHA, matching committed package/version/SDK, a non-debuggable unsigned APK and an existing persistent signing identity; it refuses key or artifact replacement. It aligns, signs, verifies the certificate and APK, and emits checksums plus provenance. Signing material is outside the repository.
- CI compiles debug/instrumentation/release APKs and runs JVM, lint and packaging checks. CI does not claim device instrumentation or physical TV/desktop acceptance.

## Defects found and corrected during this beta

A successful sync ACK no longer rewrites the native editor and overwrites newer queued typing. Native IME operations and hardware-key edits publish after completion while composition remains local. Empty IME key events now have one Backspace dispatch point. Rotation reuses the existing editor, preserving the text, selection and composing state. A customized TV Confirm emits the remote OK command rather than a text-editor action. Pending input is never replayed after reconnect, device change or uncertain delivery; dirty live edits pause for explicit review. Imported remote fields are not saved as local drafts or instance-state text.

The handset exposed a short-landscape layout defect: the keyboard left too little height for two control rows. The app now temporarily hides only its own status bar in that situation, restores it when leaving the mode, and scrolls longer drafts within a height-limited editor. Controls keep their touch sizes. Auto keyboard requests now wait for actual IME visibility, retry within a bounded window, defer while the live editor is unavailable, and respect manual dismissal and guide dialogs. Full-visibility and non-overlap assertions pass on the handset.

Gesture tests use bounded main-thread/visible-window synchronization because both the main surface and practice pad animate continuously; global UI-idle waits could hang despite a responsive app.

## Physical-device evidence and limits

The user's OPPO Find N3 (PHN110, Android 16/API 36) accepted the development APK and camera permission through normal Android UI. All 12 native instrumentation tests passed together on the handset: eight controller, two gesture-settings/practice and two TLS/JSON tests. Acceptance covers its folded outer display in portrait and landscape, including its installed keyboard. Transient USB disconnections were isolated by running the final suite through the same authorized device's temporary LAN ADB connection; test results were retained on the phone and read back. This is native physical-phone UI/protocol-fixture acceptance, not remote OS input acceptance.

Camera QR recognition, actual microphone speech recognition and Android-phone-to-Windows/macOS/Linux/TV application input have not been established by the synthetic fixtures. Speech tests supply hypotheses to the production draft-update path; they do not test acoustic recognition. No existing Sony/Xiaomi or YouTube/Netflix/browser acceptance is inferred. Real Mac receiver input still requires independently verified Yomado display **and input** isolation. This is a direct-APK beta, not a Google Play release; unlock, LG webOS, Bluetooth/peer routing, TV app-launch shortcuts, self-update and paid autonomous tasks remain outside its scope.
